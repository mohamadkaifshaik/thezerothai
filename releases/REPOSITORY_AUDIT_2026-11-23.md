# Dzeroth repository audit and remediation plan

**Audited revision** `ebcc38df70968d7db48fdaee849dd924c329ff7f`, fetched from `origin/main` on 2026-11-23. All paths and line numbers below refer to that revision. Scope includes the Flutter app, Go modular monolith, MLS core and platform bindings, Firebase rules and indexes, Terraform, workflows, scripts, dependency locks, and tests. This is a source and configuration audit with selected executable checks. Actual production settings, traffic, distributed artifacts, and legal agreements require separate evidence.

## Executive summary

**The most consequential gap is the boundary between post visibility and media delivery.** The API can withhold a protected post while a storage URL for the attachment continues to serve it. Release engineering also has two material exposures. Mobile builds include a GPL codec stack, and production deploy jobs resolve npm transitive dependencies after obtaining cloud credentials. The 16 findings comprise four High, eight Medium and four Low. No Critical finding was confirmed.

Scores are engineering judgments on a 1–10 scale. A 5 indicates a material control gap in an otherwise functioning system, a 7 indicates substantial controls with bounded weaknesses, and a 9 requires strong independent verification.

| Domain | Health | Basis |
|---|---:|---|
| Security | 6 | Strong request controls and ownership checks. Media delivery falls outside post authorization. |
| Dependencies and supply chain | 5 | Action and Go image pins are strong. Mobile licensing, release tool resolution, and Rust policy coverage need work. |
| Architecture and design | 7 | Domain modules, transactions and composition seams are established. One shared generator can stall all local ID allocation. |
| Quality and maintainability | 6 | Extensive tests and clear module ownership. Startup and cleanup responsibilities span one 1,001-line function. |
| Performance and cost | 6 | Bounded queries and batch reads are common. Video hashing and erasure batches have specific resource costs. |
| Tests and coverage | 7 | Substantial Go and Flutter suites. Browser persistence, cryptography integration, and video playback can regress through a green merge. |
| Compliance and governance | 6 | Consent, pseudonymous logs, export expiry, and monitoring are implemented. Avatar retirement and production promotion evidence can be lost. |

### Five immediate priorities

1. **Protect new follower-only attachments (S1).** Stop issuing permanent public references for newly protected media. Existing approved viewers can retain copies, but future access to the origin should follow the audience decision.
2. **Resolve mobile distribution terms (D1).** Review the actual AAB/IPA codec contents and corresponding-source obligations before the next distribution. The encoder explicitly selects x264.
3. **Lock the deployment toolchain (D2).** Build the Firebase CLI and its transitive graph in a credential-free job and bind deployment to that reviewed artifact.
4. **Make the production canary verifiable (G2).** Bind stage 100 to the exact revision, evidence of the stage-10 soak, and an authenticated read through the candidate.
5. **Gate the browser data paths (T1, T2).** Require the browser persistence and key-management checks on relevant changes and run the existing video round-trip test.

## Detailed findings

### 1. Security and vulnerabilities

**S1 · High · Protected-post media is served independently of the audience decision.** `backend/internal/posts/audience.go:122–139` enforces blocks and protected authors. `backend/internal/media/attach.go:57–61,86–93` checks ownership at attachment time and emits stable public full-size and thumbnail URLs. `infra/terraform/modules/media-buckets/main.tf:90–93` grants anonymous object GET. `backend/internal/media/gcs.go:14,63–67` sets a one-year public immutable cache lifetime. Someone who receives a URL can continue to obtain the object independently of follower status while it exists. This includes links to media created after protection was enabled. The disclosure in `app/lib/features/settings/presentation/protect_posts_messages.dart:15–20` mentions images already shared. Listing is restricted and possession of a URL is a prerequisite. **Fix:** Publish protected originals and thumbnails privately, store object IDs, and mint short-lived access only after the existing audience check. Account for public-to-private transitions, video range requests, cache policy and old client versions. Until deployed, gate new protected attachments or accurately disclose the exposure. Test new uploads, unfollow/block, privacy transitions and origin expiry with two synthetic users.

**Controls examined.** Firebase ID-token verification delegates to the SDK at `backend/pkg/platform/authn/firebase.go:36–38`. The bearer interceptor and session-cut check operate at `backend/pkg/platform/authn/interceptor.go:72–80` and `backend/pkg/platform/authn/session_cut.go:38–59`. Feature state and cache freshness influence revocation latency. Firestore denies direct client access at `firebase/firestore.rules:6–10`. The API uses configured CORS origins and header-based authentication at `backend/pkg/platform/httpcors/httpcors.go:33–40`. The billing provider fixes its HTTPS origin, escapes the ID, refuses redirects, bounds its response, and checks customer ownership at `backend/internal/billing/provider_revenuecat.go:37,78–108`. Webhooks check authorization and cap the body at `backend/internal/billing/webhook.go:53–58`. Media processing uses argument arrays and a read-only temp mount at `app/lib/features/media/data/video_conversion.dart:11–18` and `backend/internal/media/video.go:49–54`. The hosting CSP is in `firebase.json:28–36`. Source searches and these traces did not establish a SQL/NoSQL injection, executable deserialization, XSS, CSRF, SSRF, or traversal finding. SafeSearch receives media for classification at `backend/internal/media/video.go:177–178`. No generative-model tool executor or prompt-driven code execution was identified in the reviewed paths.

### 2. Dependencies and supply chain

**D1 · High · Native video distribution needs an explicit licensing decision.** `app/pubspec.yaml:73` and `app/pubspec.lock:395–402` select ffmpeg_kit_flutter_new 5.0.0. `app/lib/features/media/data/video_conversion_native.dart:30–33` invokes it and `app/lib/features/media/data/video_conversion.dart:17` requires libx264. The publisher identifies this variant as Full GPL. The web bundle already carries a separate notice and archive integrity value at `app/web/ffmpeg/NOTICE.txt:1–7`. No mobile distribution decision or corresponding-source process for the native bundle was located in the release records reviewed. This is a release risk. License compatibility depends on distribution and licensing arrangements. **Fix:** Inventory the codecs in the release packages, document the distribution decision with the license owner, and archive the matching sources, build instructions and notices where required. If those terms conflict with the intended distribution, replace the encoder with a reviewed platform codec and run the conversion fixture on each platform. [Publisher’s package and codec matrix](https://pub.dev/packages/ffmpeg_kit_flutter_new/versions/5.0.0)

**D2 · High · Production deploy jobs resolve npm dependencies with cloud credentials available.** `.github/workflows/release-prod.yml:80–84,123–125` and `.github/workflows/promote-prod.yml:160–166,234–236` authenticate to GCP before installing firebase-tools globally. Pinning the CLI version leaves dependency resolution and install scripts outside the repository’s reviewed lockfiles. A changed dependency can affect a job authorized to deploy production resources. **Fix:** Commit a dedicated CLI manifest and lock, install with `npm ci` in a job without OIDC permission or secrets, and produce a verified, digest-addressed deployment tool. Use the same digest for release and promotion. Verify version, integrity, and a rules/index deployment in dev before switching production.

**D3 · Medium · The Android Rust bridge is outside the core advisory and license gate.** `app/rust/Cargo.toml:18–22,30–31` declares the bridge dependency and separate workspace. `Makefile:245–248` runs cargo-deny in `crypto/`. `.github/workflows/ci.yml:148–149` scans Go and Pub locks. The mobile lock contains 31 package/version pairs absent from the core lock, including build dependencies. The updater covers Go, Pub, Actions and Terraform at `.github/dependabot.yml:7,23,49,65`. **Fix:** Run cargo-deny for both workspaces with an explicit reviewed policy, add Cargo updates for both roots, scan on a schedule and on lock changes, and fail an intentional bridge-only policy regression in a CI fixture.

**D4 · Low · Rust lockfiles retain four advisory matches with different exposure.** Both locks select crypto-bigint, libcrux-kem and proc-macro-error2 at `crypto/Cargo.lock:291,963,1454` and `app/rust/Cargo.lock:356,1164,1661`. The pinned suite at `crypto/dzmls/src/lib.rs:33–34` uses X25519 and Ed25519. The two libcrux advisories concern hybrid KEM operations. Runtime reachability from that suite was not established. The existing policy at `crypto/deny.toml:7–17` records owner acceptance of the NIST-curve timing issue and unmaintained build-time macro through 2027-02-16. **Fix:** Record target-specific dependency/feature evidence for the hybrid paths. Upgrade the parent chain to libcrux-kem ≥0.0.10 and crypto-bigint ≥0.7.6 when compatible, remove the abandoned macro through its parent, and make the existing review date machine-enforced. Replay MLS vectors across mobile and web. [Hybrid encapsulation](https://rustsec.org/advisories/RUSTSEC-2026-0330.html) · [Hybrid key decoding](https://rustsec.org/advisories/RUSTSEC-2026-0331.html) · [Timing advisory](https://rustsec.org/advisories/RUSTSEC-2026-0387.html) · [Macro maintenance status](https://rustsec.org/advisories/RUSTSEC-2026-0173.html)

**D5 · Low · Two bootstrap downloads lack content pins.** `app/android/gradle/wrapper/gradle-wrapper.properties:5` specifies the versioned Gradle ZIP without a distribution SHA-256. The initial service images at `infra/terraform/envs/prod/variables.tf:70` and `infra/terraform/envs/dev/variables.tf:73` omit the digest and feed the container at `infra/terraform/modules/cloud-run-api/main.tf:35`. The ordinary API base image is digest-pinned at `backend/.ko.yaml:8`. **Fix:** Add the verified Gradle distribution checksum, pin the bootstrap image by digest in both environments, and exercise a clean wrapper install and Terraform plan. Retain the current CI ownership of subsequent revisions.

### 3. Architecture and design

**A1 · Medium · Clock rollback can stall every ID producer in one API instance.** `backend/pkg/platform/snowflake/snowflake.go:59–80` holds the process-wide node mutex while sleeping until wall time catches up. There is no deadline or cancellation path. The shared node is created at `backend/internal/apiserver/apiserver.go:218–229`. A prolonged backward adjustment can stall otherwise independent mutations on that instance. Ordinary concurrent callers are protected against duplicate sequence allocation. **Fix:** Bound rollback handling and propagate a retryable failure to affected mutations, or implement a bounded logical-clock policy that preserves the encoded creation-time contract. Test rollback beyond the bound with concurrent callers, clock recovery, ordering and uniqueness.

### 4. Code quality and maintainability

**Q1 · Medium · API composition concentrates ordering and lifecycle responsibilities.** `backend/internal/apiserver/apiserver.go:110–1110` builds authentication, domains, lifecycle jobs, billing and HTTP routing in one function. Examples include late binding at lines 227–229, repeated lifecycle registration at 518–577, and billing-mode selection at 701–769. This makes feature changes depend on distant initialization order and complicates failure-path review. **Fix:** Extract billing composition and lifecycle registration first into typed constructors. Keep interceptor order and route registration explicit in the composition root. Run the existing route and lifecycle suites after each extraction.

**Q2 · Low · A failed build can strand a Firestore client.** `backend/internal/apiserver/apiserver.go:125–139,1109` allocates the client, then returns nil resources on subsequent setup errors. `backend/cmd/api/main.go:52–56` can close it only after a successful build. Process exit bounds the production impact, but repeated in-process initialization can retain transports. **Fix:** Install an error-path cleanup immediately after allocation, transfer ownership on success, and exercise a deliberately failing later constructor with a close-counting client.

**Q3 · Low · Redundant branch in entitlement reconciliation.** `backend/internal/billing/provider_revenuecat.go:113–127` continues when the subscription lookup fails, then tests the same unchanged lookup boolean again after checking the catalog. This obscures which conditions actually reject a grant. **Fix:** Remove the second `!ok` check on the subscription result only after accounting for the distinct catalog boolean (`known`), and run the ownership, refund, plan and sandbox fixtures.

### 5. Performance and cost

**P1 · Medium · A full video checksum runs synchronously on the Flutter caller’s isolate.** `app/lib/features/media/data/video_conversion.dart:4` allows 96 MiB. `app/lib/features/media/data/video_conversion_native.dart:55–69` materializes the encoded file, and `app/lib/features/media/data/video_source.dart:54–65` hashes all bytes synchronously when constructing the upload. Browser conversion already has the output in a worker at `app/web/video_worker.js:19–21`. Large valid selections can interrupt rendering after conversion and increase peak memory. **Fix:** Return the digest from the browser worker and stream/hash the native temp file or use a worker isolate with transferable ownership. Keep the integrity check. Compare frame stalls, peak memory and uploaded digest on a near-limit clip and on cancellation.

**P2 · Medium · One erasure step can perform 100 sequential child queries and commits.** `backend/internal/beacons/purge.go:19–27,51–80` selects up to 100 organised beacons, then issues a participant query and commit per beacon. At the configured extremes, one invocation can read 49,800 participant rows plus parents. Retry makes progress through deletions, but a large organiser can consume a worker budget and repeat parent reads. This is a bounded N+1 path. **Fix:** Add a per-invocation document/write or elapsed-time budget, reduce the parent fetch to match it, and resume using the existing eraser continuation contract. Test multiple full and partial participant pages, unchanged deletion completeness, retry and peak reads per invocation.

### 6. Test quality and coverage

**T1 · Medium · Real browser persistence and key-management failures can pass the merge gate.** `.github/workflows/ci.yml:327–334,382–409,509` explicitly makes the browser integration job advisory. Its tests exercise IndexedDB durability, vault ownership and device keys in JS and Wasm. The workflow itself records a prior persistence defect caught by a local run. **Fix:** Isolate stable persistence and key-management checks into a required, path-filtered job. Include changes to their Dart callers, binding, worker and storage dependencies. Retain failure artifacts for diagnosing intermittent browser errors. Verify a failing assertion makes the required summary fail.

**T2 · Medium · The end-to-end video fixture is absent from the CI test selection.** `app/integration_test/post_video_test.dart:35–51,54–90` checks conversion, upload bytes and inline playback. `scripts/ci/shard.sh:11` selects Flutter unit files under test/. The browser workflow names its integration targets explicitly at `.github/workflows/ci.yml:377,389,403–408` and omits the video target. **Fix:** Serve the checked-in clip to the test driver, run the web fixture for media/composer/player/worker changes, and exercise native conversion on an Android target for codec changes. Confirm failures in either conversion or actual playback fail the relevant gate.

Billing and identity have stronger evidence than a blanket coverage-gap claim would imply. Examples include customer readback and plan matching at `backend/internal/billing/provider_revenuecat_test.go:18,101,113`, durable webhook fencing and erasure at `backend/internal/billing/webhook_integration_test.go:15–20`, and emulator-dependent identity checks at `backend/e2e/identity_smoke_test.go:39`. Integration tags, emulator prerequisites and changed-path filters matter when interpreting a green summary.

### 7. Compliance and governance

**G1 · Medium · Avatar retirement can vanish after a successful profile change.** `backend/internal/identity/service.go:780–781` calls the retirement hook after committing the profile. `backend/internal/identity/media_retire.go:81–93` logs handoff failure without persisting a retry. The success-on-publish-failure contract is exercised at `backend/internal/identity/media_retire_test.go:147–169`. With retirement enabled, the old public objects can survive the intended grace until account deletion. The production IaC default is explicitly off at `infra/terraform/envs/prod/variables.tf:654–657`. **Fix:** With retirement enabled, persist an idempotent intent in the profile transaction using the existing outbox pattern. On delivery recheck ownership and current use before tagging. Test a committed change followed by process loss and duplicate delivery. Track overdue work without logging object URLs.

**G2 · High · Full production promotion can proceed without evidence of a successful canary.** `.github/workflows/promote-prod.yml:147–156,243–263,312–339` requires a recorded GO verdict and verifies the candidate digest, but the 15-minute observation period is a log reminder. Stage 100 moves traffic before its smoke request. Both that request and the candidate probe at `.github/workflows/release-prod.yml:170–174` call /health, which returns a constant 200 at `backend/pkg/platform/health/health.go:8–13`. The repository provides an operator-authenticated smoke at `scripts/promotion/prod-smoke.sh:2–12`. **Fix:** Persist stage-10 revision, digest, timestamp, baseline and smoke result. Re-read live traffic and validate that evidence before changing traffic to 100%. Require an authenticated, read-only business operation through the candidate and a rollback target. Keep liveness cheap. Test skipped stage 10, stale evidence, revision replacement, failed dependency and a replay of an already-completed promotion.

**Controls examined.** The API uses keyed log pseudonyms (`backend/pkg/platform/logger/logger.go:102–109`), client-safe error conversion (`backend/pkg/platform/apierr/apierr.go:72–87`), and a consent store before enabling telemetry (`app/lib/app/bootstrap.dart:178–205`). Export objects are private with soft delete disabled and a seven-day lifecycle (`infra/terraform/modules/media-buckets/main.tf:118–139`). Production declares weekly Firestore backups (`infra/terraform/envs/prod/main.tf:87–89`). TLS termination is documented at `backend/cmd/api/main.go:58–63`. Uptime, 5xx, admin and stuck-outbox monitoring exist at `infra/terraform/modules/monitoring/main.tf:187,218,299,550`. The local setup and environment variables are documented at `README.md:35–61`; secrets, state and signing stores are covered by `.gitignore:1–16` and `app/android/.gitignore:10–14`. Cloud transport, encryption-at-rest key settings, retention after a restore, alert delivery and operator access were not attested against production.
