## Checks requested by W8-9
1. **No data collection: verified.** No `TextField`, form, checkbox, consent prompt, analytics call, Crashlytics key or log, `SharedPreferences`, drift or secure-storage write in any W8 file. Creator tools only displays the `GetMe` profile already in memory.
2. **No RPC and no repository / API-client import under `app/lib/features/shells/`: verified** (I-3).
3. **No new package and no platform permission: verified.** Empty W8 diff for `app/pubspec.yaml`, `app/pubspec.lock`, `app/android/`, `app/ios/`, `app/web/`, `firebase/`, `proto/`. `url_launcher` was already a dependency; Calls uses no permission API.
4. **Deep links: verified.** `deepLinkTarget` matches only `/post/<19 digits>`, `/u/<uid>`, `/profile/<handle>`, and a test asserts the four shell paths return null. Push-notification taps map fixed types to fixed paths. Typed URL, reload and cold start never open the pop-up (I-1); history restore is closed by the M-1 fix.
5. **`mailto:`: verified.** `mailto:<address>?subject=Advertising%20enquiry`: fixed pre-encoded subject, no body, no uid, handle or device data; the address comes only from the constant, which ships as `null` (no contact affordance rendered). A fake-launcher test asserts the exact URI.
6. **Copy against W8-5's may-not list and ADR-0026 D3: verified, apart from L-1.** No purchase, reservation or sign-up control, no external `https` link, no urgency or scarcity, no date other than the user's join month, no amount other than `kPremiumPlans`. The only buttons are Back, the pop-up's Close and "Email us" (off). Prices: ₹235/month and ₹850/month from `kPremiumPlans`, each followed by "incl. GST" and spoken "including GST": the total payable, as Indian price-display rules expect. No annual price, trial or discount.
7. **Tap-only (F7): verified after the M-1 fix.** The only call that pushes `premiumPath` is `openShellEntry` (`shell_entries.dart`), reached only from the drawer row and the More menu; any other push or restore is refused by `_premiumPushAllowed`.
8. **Server side: verified.** `FeatureShells` is only in `config.go` (`LoadSpec("SHELLS", "shells", flags.Off)`) and `flags.NewRegistry`, so it is reported only through `GetMe.enabled_features` and gates no RPC. Terraform `feature_shells*` default off / empty allowlist / 0 percent, with validation. The ceiling has `SHELLS` dev allowlist 3; prod `on` (F2) is in ADR-0026 D5 and `docs/runbooks/shells.md` (Q1 default). No secret added.

## Note for the founder: the store-review risk you accepted (ADR-0026 D6)
Wording checked on 2026-10-28; recheck at the prod raise and before each store submission.
- **Apple 2.1 (App Completeness):** "...placeholder text, empty websites, and other temporary content should be scrubbed before submission." Four "coming soon" pages are the textbook case.
- **Apple 3.1.1 (In-App Purchase):** features unlocked by subscription "must use in-app purchase", and apps may not include "buttons, external links, or other calls to action" to other purchase methods (the 2025 US-storefront exception does not cover India). We have no button and no link, so no steering, but a reviewer seeing subscription prices with no IAP product can ask under 2.1 or 3.1.1. iOS ships only after the Apple launch, so this applies to the first iOS submission.
- **Google Play Payments policy:** apps "requiring or accepting payment for access to in-app features ... must use Google Play's billing system". Showing prices with no transaction does not breach it on its face; a link out or a non-Play purchase path would (forbidden by D3).
- **Google Play Minimum Functionality:** "apps should provide users with a basic degree of functionality". The app as a whole is functional, so the risk is low; Apple 2.1 is the higher risk.
- **Unchanged from D6:** a rejection is a rollback trigger; drop the cited kind from `kVisibleShells` for that store build (web keeps it) or set `shells` off. **Option, not a finding:** leaving Premium (and, for Apple, all four pages) out of the first store submissions removes most of this risk at no cost to web.

Sources: [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) · [Google Play Payments policy](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en) · [Understanding Google Play's Payments policy](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en) · [Functionality, Content, and User Experience](https://support.google.com/googleplay/android-developer/answer/9898783?hl=en)
